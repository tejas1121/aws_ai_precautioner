1. Security and Privacy in AI

When building an AI system, you need to protect both:

Data

and

AI system/model

from unauthorized access, leakage, manipulation, and misuse.

   Protection        Control          Protection
        ↓               ↓                ↓
 Encryption          IAM          Guardrails
 Privacy             Roles        Monitoring
2. Security vs Privacy

They are related but different.

Security

Protects systems and data from:

Unauthorized access
Attacks
Modification
Data theft
Destruction

Example:

Only authorized employees can access an S3 bucket.

Privacy

Focuses on how personal/sensitive information is collected, used, stored, and shared.

Example:

A customer’s medical information should not be unnecessarily exposed to an AI model.

Memory

Security = protect data/systems
Privacy = protect people's information and its proper use

6. Data Privacy Techniques

Common techniques include:

Data minimization

Only collect/use the data actually required.

Instead of sending:

Name
Address
Phone
DOB
Email
Medical history
Salary

if the AI only needs age range:

Age group

Use only what's necessary.

Anonymization

Remove identifying information so individuals cannot reasonably be identified.

Example:

Tejas Burkul → Customer_12345

However, simply replacing a name with an ID isn't always true anonymization if the person can still be re-identified.

Pseudonymization

Replace identifying information with pseudonyms/identifiers while retaining the ability to associate the data with the original person under controlled conditions.

Exam distinction:

Anonymization → identification is intended to be removed
Pseudonymization → identifiers are replaced but linkage may still be possible

PII detection

Amazon Comprehend can detect PII in text.

Amazon Macie can discover sensitive data in Amazon S3.

Bedrock Guardrails can help detect/filter PII in GenAI interactions depending on configuration.

8. Why Monitoring Matters

Suppose your fraud model initially performs well.

After six months:

Training environment
        ↓
Customer behavior changes
        ↓
Input distribution changes
        ↓
Model performance decreases

The model may still be running normally from an infrastructure perspective, but its ML behavior has degraded.

That's why AI systems need continuous monitoring.

9. AWS Shared Responsibility Model ⭐⭐⭐

This is one of the most important AWS security concepts.

The fundamental idea:

AWS is responsible for security OF the cloud. The customer is responsible for security IN the cloud.

AWS responsibility

AWS manages security of the underlying infrastructure:

Physical data centers
Physical servers
Networking infrastructure
Hardware
Managed-service infrastructure

Think:

AWS
 ↓
"Is the underlying cloud infrastructure secure?"
Customer responsibility

The customer is responsible for how they configure and use AWS services.

Examples:

IAM permissions
Data
Encryption configuration
Application security
Access policies
Security configurations
How AI services are used

Think:

Customer
 ↓
"Am I using/configuring the cloud securely?"
10. Shared Responsibility Changes by Service

The exact division depends on the AWS service.

For a managed service, AWS manages more of the underlying infrastructure.

For example:

Amazon Bedrock
       ↓
AWS manages underlying infrastructure
       +
Customer manages:
- Prompts
- Data
- IAM
- Application
- Configuration
Exam trap

❌ "AWS handles all security because it is a managed service."

Wrong.

Managed service does not eliminate customer security responsibilities.

Even though implementing data engineering pipelines is outside the hands-on scope of AIF-C01, you should understand the security best practices conceptually.

① Least privilege

Only give a data pipeline access to the data it actually needs.

Pipeline
   ↓

   ✓

Unrelated databases
   ✗
② Encrypt data

Use encryption for:

Data at rest
Data in transit
③ Protect credentials

Don't hard-code credentials inside:

Scripts
Notebooks
Configuration files

Use appropriate AWS identity/credential mechanisms.

④ Control access

Use:

Appropriate authentication/authorization
⑤ Data classification

Example:

⑥ Data validation

Before using data for ML:

Validate formats
Check missing values

🧠 AIF-C01 Exam Traps
Trap 1

"AWS is responsible for protecting customer data."

Too broad.

AWS secures the underlying cloud infrastructure, while customers have responsibilities for their data and configuration.

Trap 2

"Encryption protects against unauthorized users accessing data."

Generally yes, but encryption alone isn't sufficient. You also need proper access control and key management.

Trap 3

"Model Monitor detects model bias."

Not its primary purpose.

Clarify → bias + explainability

Model Monitor → production monitoring/drift/model quality

Trap 4

"Macie encrypts sensitive data."

❌ Not its primary purpose.

Macie → discovers/classifies sensitive data in S3.

Trap 5

"Network Isolation encrypts training data."

❌ No.

Network Isolation → restricts network access from the training container.

Trap 6

"Security and privacy are the same."

❌

Security protects systems/data.

Privacy governs the appropriate handling and protection of people's information.
